# Milestone 1

Implement this milestone in /app/main.c.

 'From the Morse Code sheet you should be able to understand the timing required to receive messages in Morse Code' and 'In this challenge you will have access to acceleration readings from a Morse Code Key using the API defined in mock_sensor.h'
You will observe the motion of the mock Morse Code key by reading the acceleration of the key in 3 dimensions in units of g (9.8 m/s/s). By observing the key through a defined API in mock_sensor.h, you must decode a message that is being sent by a mock operator. The downward motion of the key is registered in the z axis of the accelerometer.

The essence of this challenge is to read and understand the Morse Code from the pdf file, morse-code-sheet.pdf, and to monitor the operation of a Morse Code key from acceleration data from a mock sensor on the key with a given API. From the Morse Code sheet you should be able to understand the timing required to receive messages in Morse Code. In this challenge you will have access to acceleration readings from a Morse Code Key using the API defined in mock_sensor.h. You will call the mock_sensor API to get the sample number and the 3 acceleration values. You need to calculate the acceleration of the key in the z axis using the size of the gap as 2.0mm and the transit time down when the operator is pushing the key will vary in the range of 3-6 msec. The travel time going up when the spring is restoring the key will vary in the range of 4-5 msec. When the key reaches the DOWN position it stops within 0.1 msec. When the key reaches the UP position it stops within 0.2 msec. The polarity of the z axis acceleration is negative for downward (in the same direction as gravity).

You will call the mock sensor API to get readings from mock accelerometer. This will return true if a new reading if available. The structure defined in mock_sensor.h will be filled in. You can inspect the sample rate and the sample number and the x,y, and z acceleration. x and y are perpendicular to the motion of the key. The z acceleration is in the upward and downward direction traveled by the key. The sampling time of the accelerometer is 100usec. Note that because the acceleration when hitting the top or bottom stop can be less than 100usec, these accelerations might be missed so you cannot count on catching the large acceleration when the key reaches an upper or lower stop.

Note that in the data sheet morse-code-sheet.pdf the times are in units of the time of the dot. The speed of the Morse Code keying in the test will set that unit time between 100 and 250 msec. This time will not vary over the message. It will be set at the beginning and will be consistent throughout the message. The travel time of the key will still be in the range of 3-6 msec irrespective of the speed of transmission.

The message is comprised of upper case ASCII characters and spaces only with a maximum length of 50 characters. It will end when the key remains in the UP position (the mock operator is not pressing on the key) for a duration of 5 seconds. At that point you should output the decoded message followed by a '\n' to stdout.
